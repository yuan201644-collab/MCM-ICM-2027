# 美赛论文英中对照版

把一篇 PDF 论文做成"能直接读、格式统一"的中英对照 Word。产出的版式与
`研读材料\12篇研读\2022A_2209466_自行车功率曲线\2209466_英中对照.docx` 完全一致。

## 什么时候用

- 要把一篇 MCM/ICM 论文译成中文给队里读
- 要求"格式统一"（术语表在首页、每段英文下接中文、公式和表格不能丢）

## 输入

一篇论文 PDF + 一份 `paper.json`（论文元数据与术语表）。`paper.json` 由执行者读完论文后手写，
字段见 `reference/paper.example.json`：

| 字段 | 说明 |
|---|---|
| `pdf` | 原 PDF 绝对路径 |
| `workdir` | 中间产物目录（会建 `eq/`、写 json 与图片） |
| `out_docx` | 输出 docx 绝对路径 |
| `title` | 封面标题，如 `"2200084 英中对照版"` |
| `footer_prefix` | 页脚前缀，如 `"2200084 英中对照版 · 第 "` |
| `pages` | 正文页（0 基），**跳过目录页** |
| `en_only_pages` | 只排英文的页（参考文献、附录，0 基） |
| `terms` | 术语表 `[英文, 中文, 说明]`，18 条左右，按首次出现排序 |
| `gloss` | 译文里首次出现时括注英文的词对 `[中文, 英文]` |
| `fig_texts` | 图内文字对照 `{图片文件名: [[英文, 中文], ...]}` |
| `figure_note_for` / `figure_note` | 何时在图题下加中文标签注（图题文本 + 注释内容） |
| `batches` | 翻译批次数，默认 8 |

## 输出规格（不要改）

| 元素 | 规格 |
|---|---|
| 页面 | A4，左右边距 2.4 cm，上下 2.2 cm |
| 英文正文 | Times New Roman 12 pt，两端对齐，首行缩进 0.74 cm，行距 1.12 |
| 中文译文 | 微软雅黑 10.5 pt，深蓝 `#1F4E79`，浅蓝底 `#F3F7FB` + 左侧竖线 `#9CC0DE`，左缩进 0.15 cm、首行 0.6 cm |
| 英文术语 | 首次出现标蓝 `#2E74B5`；中文行对应位置括注英文原词 |
| 标题 | 英文 TNR 16/14/12 pt 粗体，中文雅黑对应字号粗体 |
| 术语表 | 首页三线表，列宽 0.9/5.4/4.2/5.7 cm，9 pt |
| 图表 | 图宽 `min(原宽, 445) pt` 居中；图表题中英双语；表格整块贴原图，**不切片** |
| 页标记 | 每页正文结束插 `— 原文第 N 页 —`（9 pt 灰） |
| 页脚 | 居中 `… · 第 X 页`（PAGE 域，8 pt 灰） |
| 文末 | 一行说明公式/表格为矢量图、可按页标记回原文对照 |

## 六步流程

```bat
set MCM_CFG=D:\...\papers\2022B_2200084\paper.json
python extract.py        :: items_full.json / eq_map.json / 图片
python make_tables.py    :: table_map.json（表格整块裁图）
python make_figs.py      :: fig_map.json（复合图整块裁图）
python repair_eqs.py     :: 补裁"正文排版型"公式（以 (N) 或含等号的行为锚点）
python make_toc.py       :: toc.json（第 2 页目录，可跨页）
python batch.py          :: batch1..N.json（待译条目）
:: 派 subagent 翻译 batchN.json -> pN.json（见下）；目录另派一批 -> toc_zh.json
python merge.py          :: zh_full.json（含完整性自检）
python build.py          :: 出 docx
```

脚本都在 `scripts/`，全部只读 `MCM_CFG`，不要改路径常量。

## 翻译交给 subagent（每个批次一个）

提示词模板：

> 读 `<workdir>\batchN.json`（数组，元素 `{id, kind, en}`），把每条 `en` 译成简体中文，
> 写 `<workdir>\pN.json`（对象，`{id: 中文}`，**key 与数量必须与输入完全一致**）。
> 规则：忠实、完整、不增删；数字/单位/公式符号/图表编号原样；`Figure N`→`图 N`、
> `Table N`→`表 N`、`Section N`→`第 N 节`；heading 保留编号；caption 用中文冒号；
> `• ` 前缀保留；学术书面语，不用口语。
> 术语必须用这份对照（其余按上下文统一）：`<把 paper.json 的 terms 贴进来>`。

回收后跑 `merge.py`：缺 key 会直接报错退出——**这是唯一的质量闸门**。

## 质检清单（交付前逐条过）

1. `merge.py` 报 `missing 0`
2. Word 打开页数合理（一般 40–55 页），首页术语表在**一页内**
3. 抽查 3 页：公式在图、表格是整块、中文块有底色和左竖线
4. 全文搜 `where, is` —— 若出现空位，说明该段行内符号个数不匹配（程序会宁空不错，可接受）
5. 每页有 `— 原文第 N 页 —`
6. 参考文献页只有英文
7. **成品 PDF 全文扫这四个字符串**（都能用 `pymupdf` 直接数出来，不必翻页）：
   `[\^_]\{`（上下标标记没渲染）、`关注数学模型`/`MATHmodels`（水印没清）、
   `←`（伪代码没裁）、`where, is`（行内符号空位）。前三个必须是 0。

## 已知坑（都是踩过的）

- **公式是矢量图**，文字层里没有，抽取时会整块消失 → 由 `extract.py` 的行带逻辑裁成
  `eq/` 图片挂到段落下方；行内符号只有在"符号个数 == 中文'为'空位数"时才插入。
- **表格会被打散成单行碎片** → `make_tables.py` 以 `Table N:` 题注为锚整块裁图，
  跨页表按段拼接；判定表尾用"词数 ≥ 20"，不要用句号（单元格没有句末标点）。
- **复合图会被拆成标签文字**（如图 11 那种"表头 + 6 张子图"）→ `make_figs.py`
  从题注向上收集短标签段，跨度 > 120 pt 即整块裁图。
- **带底色的色块会被误判成公式** → `build.py` 用 `_colorful()` 过滤饱和度高的图。
- **数字行会被逐条翻译** → 纯数字段合并成一行灰字，不配译文。
- **表题可能在表的下方**（2200084 的 Table 1/2/3 都是"表在上、题注在下"）→ `make_tables.py`
  先向下找单元格，找不到就向上找；向上时用"最近的标题/题注"或 `caption.y0-240` 定顶边，
  并把落在裁切带内的所有段落都加进 `skip`，否则会出现"碎片文字 + 表图"重复。
- **页眉页脚会混进正文**（`Team # 2200084` / `Page 5 of 21`）→ `build.py` 用 `HEADER` 正则整行跳过。
- **标题常被拆成两个 item**（`1.3` 和 `Overview of our work` 同 y）→ `build.py` 在渲染前合并。
- **纯符号段的中文=英文** → 相等时不再重复输出中文块（否则每行公式都会出现两遍）。
- **公式/伪代码是矢量排版**，抽出来就是碎片（如 `2 while h(t)and h(t)`），属源文件特性，不必强修。

## 交付

docx 存到论文目录，并在同目录导出一份同名 PDF（Word COM 导出，用于确认版式），
两者一起提交。

- **伪代码/算法也会被当成正文翻译**（Update: V (t+1)、while 行）→ uild.py 用 CODE
  正则（while/for/if/else/end/return/Algorithm/Update/Set/Compute/Initialize 或含 ←）只排英文。
- **纯符号段**（αijv(t)、Xij = dwater）译文与原文相同或全无汉字 → 只排英文、10.5pt、间距压到 3pt，
  不生成中文块，否则每行都会重复两遍。
- **图内文字对照不是自动的**：ig_texts 必须逐图手写。凡图里有英文标注（流程图、地图、网络图、
  Sankey、带图例的柱状图）都要给 {图片文件名: [[英文, 中文], ...]}，否则读者只能看图上的英文。
- **标题编号会被拆成独立的 item**（2 与 Assumptions）→ 合并时要同时改 	ext 和 sents[0]，
  因为 heading 分支取的是 sents[0]。

- **上下标会丢**：PDF 里 `v_ij^(t)`、`S_i`、`β_i` 是“小字号 + 基线偏移”的独立 span，直接拼接文本会被拍平成 `v(t)ij`、`Si`。
  `extract.py` 已按“字号 ≤ 行内最大字号×0.82 且基线抬高/下移 >0.6pt”输出 `^{...}` / `_{...}` 标记，
  `build.py` 的 `_emit()` 再把标记渲染成真正的上/下标 run。
  **注意**：改抽取会改变 item 下标，必须用文本匹配把旧 `zh_full.json` 重新映射
  （`_work/remap_zh2.py` 的做法：heading/caption 的 key 是 `str(idx)`，para 的 key 是 `"%d.%d"`，两侧都要按 kind 取对）。

- **伪代码块（Algorithm N）也会被拆成碎片**：行号、`←`、上下标各成一行，正文里出现
  `2 > h_lowestdo` / `2t1 ← t · Δt` / `Update: V (t+1)` 这种残片，且中英文各重复一遍。
  `scripts/make_algs.py` 以 `Algorithm N:` 为锚点整块裁图（裁切时**把英文题注一起裁进去**），
  `work/alg_map.json` 与 `eq_map.json` 同构，`build.py` 已一并读取并在图片下方补中文题注。
  裁剪边界经验：`x0 < 86` 视为正文行、行间距 `> 40pt` 断开、末尾再剪掉"首字母大写 + ≥7 词"的散文行。
  **锚点不要写死冒号**：2400996 的题注是 `Algorithm 1 Lamprey Population Iteration Simulation`
  （无冒号），正则改成 `^Algorithm\s*\d+\b`；左边界也别写死 86pt，用锚点行 x0 做参照
  （该论文缩进从 71pt 起），否则第一行 `Input:` 就会被判成正文而整块裁不出来。

## 目录（Contents）也要排进去

原 PDF 的目录页在 `pages` 里是被跳过的；现在产物第 2 页放「中英对照目录」：

1. `python make_toc.py` → `work/toc.json`（`{"entries": [[level, "1.2", "Title", 页], ...]}`）。
   目录常分两种排法：点线版（`1.1 Background ...... 2`，一行一条）和 LaTeX 版（编号、标题、页码是三条
   独立 line，x 不同）；脚本先按 y 把同一行的 span 拼回一条再解析。
   **目录可能跨两页**（2224021 就跨 2–3 页），脚本最多连读 3 页，某页解析结果 < 2 条就停。
2. 派 subagent 译标题 → `work/toc_zh.json`（`{"0": "中文", ...}`，key 是 entries 下标）。
3. `build.py` 读这两个文件，在术语表之后、正文之前排一页目录：`编号 + 中文（English）…… 页码`，
   页码是**原 PDF 页码**，与正文的 `— 原文第 N 页 —` 对应。

## 二次校订（8 篇批量做完后才发现的符号/版式问题）

- **上下标标记只在英文侧渲染**：`add_en` 走 `_emit()`，`add_zh` 却是裸 `add_run`，
  于是中文块里原样打印 `M ^{1}`、`p_{1}`。→ `add_zh` 也走 `_emit(font="微软雅黑")`，
  并把 marker 前的空格吃掉（`PRE_MARK`），否则会显示成 `M ¹`。
- **段落被 PDF 行宽从句子中间劈开**：上一段没有终止符、下一段以小写/数学字母开头时，
  中文块会插进英文句子中间，读起来是断的。`build.py` 里加了 `TERM`/`CONT` 合并（可跨一页），
  中间的空 `img` 条目要能穿透，否则一个被清掉的二维码就挡住了合并。
  **别把 `\d+\.` 当续行**：编号列表 `1. … 2. …` 会被串成一段。
- **纯数学行被当成标题**：`1 −p1p2. If player…` 命中 `^\d+` 的标题启发式，排成 13pt 粗体。
  → `_is_num_heading()` 要求不含 `=+−<>≤≥^_{` 等符号。
- **标题的纯数字译文会重复**：`2.3` 的译文还是 `2.3`，标题分支会印两遍。
  → 译文与原文相同或没有汉字就不印中文块（caption 同理）。
- **微信公众号水印三种残留**：① 正文整串（`微信公众号：数学模型 微信号：MATHmodels`）；
  ② 被切掉一半，只剩 `关注 2` / `^{关注}`（水印字号小，会被抽成上标）；
  ③ 图里（二维码小图 297×150、316×159，以及半透明粉字压在公式裁图上）。
  → `clean_wm.py` 清 ①②（`(?<![\u4e00-\u9fff])关注(?=\s*[0-9A-Za-z])` 才不会误删"备受关注"）；
  `deshade_eq.py` 把 eq/alg 裁图里 `r-g≥8 且 r-b≥8` 的像素刷白（水印可能是极淡的 255,242,242）。
- **纯文本排版的公式抓不到**（2429211 的线性规划）：`extract.py` 只把"矢量图形"当公式，
  这套 LP 是正文字体排的，结果被拆成一堆 `minimize` / `∀t∈[1,T]` / `ℎ𝑖,𝑡≤𝐹𝑖` 单行碎片。
  这类块只能整块裁图（用行坐标定 y0/y1，写进 `alg_map.json`，格式与 eq_map 同构）。
  `repair_eqs.py` 做了半自动版：以右缘 `(N)` 为锚点，向上/向下收集"连续数学行"整组裁图，
  已覆盖的条目先剔除；`--unnum` 还会把"含等号、缩进、≤9 词"的无编号展示公式也当锚点。
  但 2429211 有些公式在文字层里已经碎到没有 `=`（`𝑤1𝑖=` 只剩 `𝑤1𝑖`），脚本认不出来，只能按行坐标手工裁。
- **目录页的水印会污染条目**：2429211 的末条被拼成 `Memo To The ĲC A Notation 21 关注数学模型`。
  `make_toc.py` 里做了三件事：过滤水印行、`Ĳ`→`IJ` 连字还原、把"无编号但有页码"的行按条目解析
  （`A Notation 21`、`References 24`、`Appendices 23` 都属这类）。
- **目录的制表位别顶到版心右界**：A4 左右各 2.4 cm 时版心 16.2 cm，制表位写 16.1 cm 会让两位页码换行，
  目录最后一条只剩点线没有页码；用 15.7 cm。
- **位图公式会整条消失，编号却还在**（2409949 的 (1)(2)(4) 等 5 条）：有些论文把公式本体存成
  小位图，文字层只剩右缘的 `(N)`。`extract.py` 只把大图当插图、`make_eqs.py` 只认文字/矢量公式，
  两头都漏，成品里就出现一个孤零零的 `(1)`。
  → `fill_bitmap_eqs.py`：以右缘编号为锚，收集同水平带的图片块 bbox，整条裁图写进 `eq_map.json`
  （`skip` 掉编号条目）。12 篇实测只命中 2409949 的 5 条，其余 0 条，无误伤。
- **审计公式要按编号查，但别被旧格式骗了**：`audit_eq2.py` 逐个比对右缘 `(N)` 是否被裁图覆盖。
  两个假阳性要排除：① 旧 `eq_map`（2022A）是 `{idx: [...]}` + `inline`，公式直接挂在条目号上、
  没有 `skip`，要按"数字 key 即覆盖"和"±3 邻近挂载"判定；② 编号若连同公式一起在图里，
  文字层只有重叠的长正文段落，不能把它当成"漏掉的编号"（要求命中条目的文本本身就是 `(N)`）。
- **行内数学符号丢失（`where, is` / `式中，为`）**：2209466 把 γ、ρ、A_p 这类符号画成矢量小图，
  文字层没有字符；旧脚本只把小图挂到中文侧「，为」空位，且要求小图数 == 空位数，
  数量不等就整批丢弃，结果英中两侧都缺主语。→ `fix_inline_symbols.py` 按原 PDF 逐字补回符号
  （用 `_{}` 让 `_emit` 渲染成真下标），并删掉这些条目的 inline 小图，避免符号出现两遍。
- **目录标题里也会混进水印**：`微信号：MATHmodels Ideal Water Determination Algorithm`、
  `微信公众号：数学模型 Problem Restatement`——水印与标题被抽成同一行，`make_toc.py` 原来
  只过滤"整行都是水印"的情况。现在 `fix()` 行内清 `WM_INLINE`，只删水印串、保留英文标题。
